# Spec Delta

## Purpose

Make videos in which a brand's own characters act in one shared set: first frames composed from the
characters' reference stills, animated by an image-to-video model with a camera move in every shot,
cut to the narration, at a known and bounded cost.

## ADDED Requirements

### Requirement: Shot list

A character project SHALL describe its video in `edit/shots.json`. It holds a `world` text, a `cast`
(name → reference still path + description) and ordered `shots`, each with an `id`, a narration
`line`, and either a `library` clip id or a `cast` list with `frame`, `motion` and `camera` texts.
The tools SHALL reject a shot that names a cast member missing from `cast`, or whose reference still
does not exist.

#### Scenario: Unknown cast member

- **WHEN** a shot lists `"cast": ["hero", "guide"]` and `cast` defines only `hero`
- **THEN** the keyframe tool exits before any paid call, naming the shot and `guide`

#### Scenario: Missing reference still

- **WHEN** a cast entry points at a file that does not exist
- **THEN** the tool exits before any paid call and prints the missing path

### Requirement: Keyframes from reference stills

The keyframe tool SHALL write `edit/keyframes/<shot id>.png` at 9:16 (or the project aspect) for each
shot with a `frame`. It SHALL send the listed characters' reference stills as references and the
`world` text in the prompt. It SHALL leave an existing keyframe alone unless asked to redo that shot.

#### Scenario: One pass

- **WHEN** the keyframe tool runs on a shot list with 5 `frame` shots and no keyframes yet
- **THEN** 5 PNGs exist in `edit/keyframes/`, each with a portrait aspect ratio of 9:16 ± 2%

#### Scenario: Rerun keeps approved frames

- **WHEN** it runs again with no shot ids
- **THEN** no paid call is made and the 5 files are unchanged

### Requirement: Candidates and contact sheet

With `--n K`, the keyframe tool SHALL write K candidates per shot as `<id>_1.png … <id>_K.png`. It
SHALL also write a contact sheet labelled with the file names, so a candidate can be picked by copying
it to `<id>.png`.

#### Scenario: Two candidates

- **WHEN** it runs for one shot with `--n 2`
- **THEN** `<id>_1.png`, `<id>_2.png` and a contact-sheet PNG that shows both labels exist

### Requirement: Group shots from an approved keyframe

A shot with a `base` keyframe path SHALL be generated by editing that image, with only the newly listed
characters sent as extra references. This keeps characters already approved in `base` as they are.

#### Scenario: Adding two characters

- **WHEN** a shot has `"base": "keyframes/duo.png"` and `"cast": ["c", "d"]`
- **THEN** the request carries 3 images (base first, then c and d) and the result is written to `keyframes/<id>.png`

### Requirement: Image-to-video per shot with a camera move

The animate tool SHALL turn each shot's keyframe (or its `src` still) into `edit/shots/<id><suffix>.mp4`.
The prompt SHALL be the shot's `motion` and `camera` texts plus a fixed tail asking for continuous
camera movement and unchanged character design. It SHALL refuse a shot whose `camera` text is empty.

#### Scenario: Missing camera move

- **WHEN** a shot has `motion` but no `camera`
- **THEN** the animate tool exits before any paid call, naming the shot

#### Scenario: Clip written

- **WHEN** a shot is animated with the default model
- **THEN** `edit/shots/<id>.mp4` exists, has a video stream with portrait aspect, and a frame strip PNG is written to `edit/verify/`

### Requirement: Selectable models

The animate tool SHALL accept a model name from a registry and default to the cheapest registered model
that the workspace has verified. Each registry entry holds its allowed durations and price per second.
An unknown model name SHALL be rejected, with the registered names listed.

#### Scenario: Unknown model

- **WHEN** `--model foo` is given
- **THEN** it exits listing the registered model names

### Requirement: Exact-length clips fitted to narration

With `--dur fit`, the animate tool SHALL request each clip at the length its shot needs in the
timeline plus a 0.2 s handle. If the model only allows fixed durations, it SHALL request the smallest
allowed duration that covers that length. It SHALL refuse a shot whose needed length exceeds the
model's longest duration.

#### Scenario: Any-duration model

- **WHEN** a shot needs 3.07 s and the model accepts any duration
- **THEN** the clip is requested at 3.27 s and the written clip is at least 3.07 s long

#### Scenario: Fixed-duration model

- **WHEN** a shot needs 7.13 s and the model allows only 5 or 10 s
- **THEN** the clip is requested at 10 s

### Requirement: Cost estimate before paid calls

Before sending any paid request, the generators SHALL print the number of requests and the estimated
cost in USD from the registry prices.

#### Scenario: Estimate printed

- **WHEN** 4 clips of 5 s are about to be generated on a model priced at $0.015/s
- **THEN** the output shows 4 requests and an estimate of $0.30 before the first request is sent

### Requirement: Per-run budget

The generators SHALL stop before sending any request if the run's estimate exceeds the budget. The
budget defaults to $2 and is set with `--budget`. Nothing SHALL be generated in that case.

#### Scenario: Over budget

- **WHEN** a run is estimated at $3.50 with the default budget
- **THEN** it exits without generating anything and names the estimate and the `--budget` flag

### Requirement: Spend log

Every paid request SHALL append one JSON line to `edit/gen_spend.jsonl`. Each line records the time,
tool, model, shot id, requested duration, estimated cost and output path. The tools SHALL be able to
print the project's total.

#### Scenario: Log line per clip

- **WHEN** 3 clips are generated
- **THEN** `gen_spend.jsonl` gains 3 lines whose estimated costs sum to the printed run estimate

### Requirement: Credentials stay out of the repo

Paid tools SHALL read their keys only from `vendor/video-use/.env` or the environment, and SHALL never
print a key or write it to any project file or log. A missing key SHALL stop the tool before any
request, naming the variable to set.

#### Scenario: No key

- **WHEN** the animate tool runs and no fal key is set
- **THEN** it exits naming `FAL_API_KEY` and `vendor/video-use/.env`, and nothing is written

### Requirement: Base take cut to narration

The shot-cut tool SHALL build `edit/base.mov` (1080x1920, 30 fps) from the shot clips and one narration
clip per shot. Each shot SHALL last its narration clip + 0.15 s lead + 0.25 s tail (at least 2.0 s),
joined by hard cuts. It SHALL write `edit/timeline.json` with each shot's start and duration.

#### Scenario: Timeline matches narration

- **WHEN** a shot's narration clip lasts 2.40 s
- **THEN** its entry in `timeline.json` lasts 2.80 s (±1 frame) and its voice starts 0.15 s into the shot

#### Scenario: Clip too short

- **WHEN** a shot's clip is shorter than the duration the timeline needs
- **THEN** the tool exits naming the shot and both durations, and suggests `animate --dur fit` for it

### Requirement: Music and end card in the base take

The base take SHALL mix optional music under the voice with sidechain ducking. It SHALL fade the music
out over the last 1.5 s, and end with an optional end-card image after a 0.4 s crossfade.

#### Scenario: With end card

- **WHEN** an end card of 3 s is set
- **THEN** `base.mov` lasts the sum of the shot durations + 3 s (±1 frame), and its last frame matches the end-card image

### Requirement: Base take feeds the short-form engine

`base.mov` SHALL be usable as the single source of a short-form build (one segment covering it). This
lets captions, overlay cards, SFX and loudness come from the existing engine. Caption emphasis and word
fixes SHALL be expressible relative to shot starts read from `timeline.json`.

#### Scenario: Final render

- **WHEN** the character build template is run after `base.mov` and its transcript exist
- **THEN** `edit/final.mp4` is 1080x1920 and measures -14 LUFS ± 1 with true peak ≤ -1 dBTP
